# SSH 站台管理器規格

- 版本：v0.1（規劃版）
- 平台：Windows 10 / Windows 11 本機視窗軟體
- 類型：免安裝優先；解壓縮或直接執行即可使用
- 目標：以最少的設定與操作，管理常用 SSH 站台並同時查看多台主機的終端輸出。

## 1. 使用情境

使用者有多台 Linux／Unix 伺服器，需要保存各主機的連線資料，並能一次維持多個 SSH 連線。在排查問題時，使用者可將兩個終端並排，例如同時觀察 Web 與資料庫主機的日誌。

## 2. 首版範圍

### 2.1 站台管理

- 顯示本機儲存的 SSH 站台清單。
- 可新增、編輯、刪除站台。
- 站台欄位：
  - 站台名稱（必填）
  - IP 位址或網域（必填）
  - Port（必填，預設 `22`，範圍 `1–65535`）
  - 使用者名稱（必填）
  - 驗證方式：密碼／私鑰檔
  - 密碼，或私鑰檔路徑與私鑰密碼（依驗證方式顯示）
  - 備註（選填）
- 可依站台名稱、IP 或使用者名稱搜尋。

### 2.2 SSH 連線與終端

- 由站台清單雙擊或按下「連線」建立 SSH 工作階段。
- 每台主機各自建立獨立的終端分頁。
- 可同時維持多個連線；切換分頁不會中斷其他連線。
- 提供連線中、已連線、連線失敗、已中斷等明確狀態。
- 每個終端支援：
  - 指令輸入與輸出顯示
  - Enter、Backspace、方向鍵等基本互動按鍵
  - 基本 ANSI 色彩顯示
  - 複製與貼上
  - 捲動查看輸出紀錄
  - 中斷連線與重新連線

### 2.3 雙欄並排檢視

- 可從已開啟的連線中選擇兩台主機進行左右並排。
- 左右兩側保有各自獨立的終端內容、輸入焦點與連線狀態。
- 離開並排檢視時，兩個 SSH 工作階段持續存在並回到一般分頁。
- 首版不提供「同時廣播輸入到多台」功能，避免誤執行指令。

## 3. 介面設計

採簡潔的桌面 SSH 工具工作流：左側站台清單、右側連線終端；視覺可參考傳統 SSH 客戶端的資訊密度與分頁方式，但不使用 Xshell 的名稱、圖示或介面素材。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ SSH 站台管理器       [+ 新增站台] [編輯] [刪除] [搜尋…]               │
├──────────────────────┬───────────────────────────────────────────────┤
│ 站台                 │ [Web-01 ×] [DB-01 ×] [並排檢視]               │
│ ● Web-01             ├───────────────────────────────────────────────┤
│ ● DB-01              │ root@Web-01:~$                                │
│ ○ Cache-01           │                                                │
│                      │ 終端輸出與指令輸入區                           │
│ 最近連線             │                                                │
│   Web-01             │                                                │
├──────────────────────┴───────────────────────────────────────────────┤
│ 已連線：Web-01 · 192.168.1.10:22 · 密碼驗證                          │
└──────────────────────────────────────────────────────────────────────┘
```

並排檢視：

```text
┌───────────────────────────────┬───────────────────────────────┐
│ Web-01 · 已連線               │ DB-01 · 已連線                │
│ root@Web-01:~$                │ root@DB-01:~$                 │
│ tail -f /var/log/access.log   │ tail -f /var/log/error.log    │
│                               │                               │
└───────────────────────────────┴───────────────────────────────┘
```

## 4. 資料與安全性

- 所有站台資料僅保存在本機。
- 建議路徑：`%LocalAppData%\HomegrownTools\SshManager\sites.json`。
- 密碼與私鑰密碼不得以明文寫入 JSON；使用 Windows DPAPI、綁定目前 Windows 使用者帳戶加密保存。
- 私鑰本體不複製進設定檔，只儲存使用者指定的檔案路徑。
- 不上傳站台資料、帳密或終端輸出，也不提供雲端同步。
- 連線失敗時，錯誤訊息不得回顯密碼或私鑰密碼。

## 5. 技術與發行原則

- 不限定 C#、Windows Forms 或 .NET Framework；實作技術於開發開始時再依 SSH 終端相容性、部署大小與維護性決定。
- 第一優先是免安裝使用：成品應能直接從 `release` 目錄啟動，不建立服務、不要求系統管理員權限，也不要求安裝額外的 SSH 客戶端。
- 可以假設目標 Windows 主機已具備 .NET Framework 4.x；若採用此路線，可將所需第三方 DLL 與 EXE 一起發行。
- 若選擇其他執行環境，應隨程式一併提供可攜式 runtime，或確認其為 Windows 10／11 的內建元件；不得要求使用者另行執行安裝程序。
- SSH 實作需同時支援密碼與私鑰驗證，並提供可互動 Shell 工作階段。
- 終端需能收送 Shell 資料，支援首版所需的基本 ANSI 顯示與鍵盤輸入。
- 發行：`release` 內提供 EXE 與必要相依檔案；不需要安裝程式。

## 6. 驗收條件

1. 能新增一個密碼驗證站台並儲存；重新開啟程式後設定仍存在。
2. 能新增一個私鑰驗證站台並成功連線。
3. 儲存的設定檔不含可直接閱讀的密碼或私鑰密碼。
4. 能同時連線至少兩台主機，兩個連線互不干擾。
5. 能將任意兩個已連線終端左右並排，同時持續顯示輸出。
6. 在終端執行常用指令（例如 `pwd`、`ls`、`tail -f`）可正常輸入並看到輸出。
7. 可個別中斷或重新連線，不影響其他分頁。

## 7. 暫不納入首版

- SFTP／檔案傳輸
- SSH 跳板機、Proxy、Port forwarding、X11 forwarding
- 多人共享站台、雲端同步、匯入匯出
- 完整 VT 終端機相容性、巨集與自動化腳本
- 廣播輸入到多個終端
- 行動版或 macOS／Linux 版
